# Eva — рабочие правила для агента

## Что это

Telegram-компаньон. Форк/выжимка из `Aimagine-life/Betsy` (MIT). Апстрим мёртв, не синкаемся.
Источник истины по состоянию проекта — этот файл плюс `FORK-PLAN.md`.

## Железные правила

1. **Данные и секреты — не в репозитории.** Только код. `config.example.yaml` с заглушками.
   Реальный `config.yaml`, `*.db`, `.env` — в `.gitignore`, живут в `~/.eva/`.
   Никогда не коммитить ключи, токены, пароли, реальные значения конфига.
2. **Секреты не светятся в чат.** Только путь, имя переменной, длина значения.
3. **Никаких правок на сервере.** Сервер `rdp-fi` — только рантайм. Разработка здесь.
4. **`/study` не трогать** — это метрика, а не фича.
5. **Апстрим не форкаем.** Правки идут в этот репозиторий.

## Проверка перед коммитом

```bash
npm run typecheck   # должно быть 0 ошибок
npm run build       # dist/index.js
npm test            # 33 файла, зелёные
```

Тесты гоняются на любой машине: `vitest.config.ts` подменяет `better-sqlite3`
на шим поверх `node:sqlite` (`test/shim/better-sqlite3.ts`). Нативный модуль
здесь не собирается, и из-за него падали 12 файлов с базой — они прятали
настоящие баги за «средовой» ошибкой. Не убирай алиас, не проверив, что тесты
всё ещё проходят.

## Известные особенности

- **Провайдер — это адрес + ключ.** Не зашивай новые провайдеры в код: они
  добавляются либо в `PROVIDER_PRESETS` (`registry.ts`), либо просто описываются
  в конфиге через `base_url`/`api_key`. Тот же принцип для `image_gen.base_url`.
- `loadConfig()` вызывается один раз на старте. Всё, что меняет конфиг в рантайме,
  обязано достучаться до живого роутера: `registry.onChange()` переписывает
  `config.yaml`, а `router.role(name)` резолвится лениво при каждом запросе.
  Правка файла в обход реестра — молчаливый рассинхрон.
- `self_config` пишет в YAML сразу и синхронно, но живой роутер изменение не
  видит. После него нужен `registry.setRole(...)`, а не запись в файл.
- **Деградация переключается синхронно**, прямо в `noteFailure()`. Не оборачивай
  переходы в промисы: отложенный флип флага приводит к тому, что Ева молча уходит
  на запасную модель и не сообщает об этом. Это уже было багом, тест ловит.
- `onOwnerClaimed` в `index.ts` вызывает `saveConfig` с устаревшим in-memory
  объектом и способен затереть сделанные правки.
- Генерация картинок через `modalities:["image"]` — расширение OpenRouter, не
  часть спецификации OpenAI. Переносить на другой эндпоинт имеет смысл только
  если он это умеет.
- **Индекс памяти считается в JS, SQLite не умеет.** `knowledge.stems` —
  это `indexText(topic + insight)` из `stem-ru.ts`: стемы **плюс** сырые слова.
  Сырые обязательны: «котёнок» ни одним правилом не сводится к «кот», но
  начинается с тех же букв, и префиксный поиск его добирает.
- **Формат индекса версионируется** в таблице `eva_meta`
  (`knowledge_index_version`, сейчас 2). Сменил, что делает `indexText`, —
  поднял константу, и миграция сама перестроит индекс у живого бота.
- **Никогда не пиши в `knowledge_fts` сырым текстом.** Пользовательское
  сообщение идёт в `searchKnowledge` как есть, а FTS5 читает `:` `~` `^` `"`
  `*` как синтаксис. Только через `buildMatchQuery`, который токенизирует и
  кавычит каждый термин.
- `searchKnowledge` глотает ошибки БД и возвращает пустой массив. Поменяешь на
  проброс — обычное сообщение с двоеточием уронит ход.
- **Не правь `knowledge_fts` руками.** Триггеры уже снимают и кладут строку
  обратно при UPDATE. Ручное удаление поверх триггера = двойное удаление =
  `database disk image is malformed` на следующем чтении. Вытеснение — это
  `UPDATE knowledge SET superseded_at`, а отсев делает `WHERE superseded_at IS NULL`
  в самом запросе.
- **Порядок в `rowsToRetire` — не украшение, а смысл.** `ORDER BY access_count DESC,
  timestamp DESC, id DESC` + `OFFSET keep` оставляет используемое и вытесняет
  невостребованное. Обратная сортировка с тем же `OFFSET` вытесняет ровно то,
  что работает, — так и было в первой версии, поймал тест
  `retires an unused memory before one that is in use`.
- **Все записи в память идут через `learnInsight`.** Прямой вызов `addKnowledge`
  обходит дедуп: так она могла записать «люблю грибы» сразу после «не люблю
  грибы», и обе строки оставались.
- `retireKnowledge(id, supersededBy?)` — с `supersededBy` факт **исправлен**,
  без него — вытеснен за место. Разница видна в `superseded_by` и отвечает на
  вопрос «почему Ева когда-то считала иначе».
