# Eva

Персональный AI-компаньон в Telegram. Умеет память, самообучение, голос, картинки — и
**любой провайдер LLM, какой захочешь подключить**.

Форк и выжимка из [Aimagine-life/Betsy](https://github.com/Aimagine-life/Betsy) (MIT, Wildbots 2025).
Апстрим мёртв — один сплющенный коммит, обновлений ждать неоткуда.

## Что изменилось против апстрима

Апстрим — 223 файла и 32 017 строк, из них 19 тысяч занимает режим `multi`
(Postgres + drizzle + AWS S3 + OpenTelemetry), который в реальности не работал.
Здесь осталось **61 файл и ~7 000 строк** в `src/` — только то, что действительно исполняется.

Выкинуто: `multi/`, веб-панель `ui/`, `server.ts`, `auth-relay/`, Electron-приложение,
лендинг, 16 мёртвых зависимостей (`viem`, `@aws-sdk`, `drizzle-orm`, `sharp`, `pg`, ...).
`node_modules`: 491 МБ → 138 МБ.

Переписано:
- **Провайдеры** — реестр (`src/core/llm/registry.ts`) с произвольными OpenAI-совместимыми
  адресами вместо вшитого OpenRouter. Готовые шаблоны для openrouter / openai / google /
  groq / deepseek / together / cerebras, любой свой адрес — тоже.
- **Модели** — ролевые профили (`fast` / `strong` / `study` / `embed` / `image`) с
  переключением на лету, без перезапуска.
- **Роутер** — фолбэки с общим дедлайном, а не шестью минутами тишины; ловит 5xx и
  сетевые сбои, а не только «кончились деньги».
- **Память** — русская стемминг-нормализация для FTS, семантический дедуп.
- **Личность** — границы того, что Ева может менять в себе сама.

## Провайдеры

Любой OpenAI-совместимый эндпоинт. Прописывается в `config.yaml`:

```yaml
providers:
  openrouter: { api_key: "..." }        # base_url подставится сам
  google:     { api_key: "..." }        # Gemini через официальный OpenAI-эндпоинт
  my-server:  { base_url: "http://127.0.0.1:1234/v1", api_key: "..." }

models:
  fast:   { provider: openrouter, model: google/gemini-2.5-flash }
  strong: { provider: google,     model: gemini-2.5-pro }

fallbacks:                               # перебор при кончившихся деньгах или 5xx
  - { provider: openrouter, model: qwen/qwen3-coder:free }
```

Хочется сменить модель — можно не редактировать конфиг: у Евы есть тулза
`switch_model`, и она сама переключит роль по просьбе, **проверив модель
одним запросом и откатившись, если та не ответила**. Список моделей
провайдера она тоже спросит сама (`GET {base_url}/models`).

Единственное, что требует отдельного адреса, — генерация картинок: режим
`modalities:["image"]` в чат-комплишенах не входит в спецификацию OpenAI, и
чужой эндпоинт сработает, только если он тоже это умеет. Поэтому у картинок
своя роль `image`, и она переиспользует того же провайдера: отдельный сервис не
нужен, нужен только тот, кто это умеет. Адрес при желании переопределяется в
`image_gen.base_url`.

## Установка

```bash
npm i -g github:Jzen86/eva
eva init
eva
```

`eva init` спрашивает четыре вещи — токен бота от [@BotFather](https://t.me/BotFather),
провайдера, ключ и модель. Токен и ключ вводятся скрыто, в файл попадают с
правами `600`, и в конфигбек и историю команд не попадают. Последнее, что делает
`init`, — прогоняет `eva doctor`, так что «заработало или нет» видно сразу.

Без вопросов — для скриптов, Ansible и всего такого:

```bash
eva init --token 123456:AA... --provider openai --key sk-... --model gpt-4o-mini
```

Готовые адреса есть у `openrouter`, `openai`, `google`, `groq`, `deepseek`,
`together`, `cerebras`. Свой адрес — `--provider my-llm --base-url http://10.0.0.5:8080/v1`.
Какие модели у провайдера есть, Ева спросит сама.

Повторный `eva init` рабочий конфиг не трогает. Перезаписать — `eva init --force`,
старый файл ляжет рядом как `config.yaml.init-backup`.

**Обязательных внешних сервисов нет.** fal.ai, Google и OpenRouter не нужны: ключ
провайдера покрывает и текст, и картинки. Всё, что можно включить, включается
само собой, когда появляется ключ, — см. «Инструменты».

### systemd

```ini
# /etc/systemd/system/eva.service
[Unit]
Description=Eva
After=network-online.target

[Service]
Type=simple
User=eva
ExecStart=/usr/local/bin/eva
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now eva
```

`ExecStart` указан абсолютным путём: у systemd свой `PATH`, и `eva` из
`/usr/local/bin` он может не увидеть. Путь смотрится через `which eva`.

Если `eva doctor` ругается на `better-sqlite3` — не собралась нативная часть,
на голой системе нужен тулчейн: `apt install -y build-essential python3`, потом
`npm i -g github:Jzen86/eva` заново. Это самая частая поломка при установке, и
`doctor` говорит о ней именно этим текстом.

### Диагностика

```bash
eva doctor            # что сломано и с чего начать; код возврата 1, если сломано
eva doctor --probe    # плюс живые запросы к моделям — они тратят деньги, поэтому отдельно
```

То же, что `/doctor` в чате, плюс то, что из чата не спросишь. Живые запросы без
`--probe` не делаются никогда.

## Инструменты

Тулзет — функция конфига, а не то, что осталось от прежней версии. Три уровня:

| Уровень | Что входит | Когда включается |
|---|---|---|
| всегда | память, файлы, `send_file`, shell, напоминалки, http, самоконфиг, смена модели, диагностика | всегда |
| по ключу | поиск в интернете, скиллы, картинки, селфи, голос | когда положен соответствующий ключ |
| по флагу | браузер, ssh, установка npm-пакетов | явно, в `tools:` |

Каждый выключенный инструмент объяснён одной строкой в логе на старте, так что
«молчит, потому что сервиса нет» не путается с «сломалась».

Браузер, ssh и установка пакетов выключены по умолчанию намеренно: браузер тянет
150 МБ и лезет на любые страницы, ssh исполняет команды на другом хосте,
установка пакета запускает его install-скрипты. Это другой уровень доверия, и
выдавать его по умолчанию — значит тащить и риск, и вес туда, где их не просят.
Ева сама их не включает:

```yaml
tools:
  browser: true       # и npx playwright install chromium
  ssh: true
  npm_install: true
```

### Что Ева может выполнить сама

У `shell` и `ssh` нет белого списка команд «с которыми можно» и нет чёрного
списка «от чего нельзя». Есть список бинарников, которые **не могут ничего
записать ни в одном режиме**: `ls`, `cat`, `tail`, `df`, `ps`, `grep`, `ss`,
`journalctl`, `systemctl status`/`is-active`/`show`, `find` без `-exec`, `sqlite3`
с `SELECT`. Это идёт сразу и молча.

Всё остальное не выполняется, а **ставится на паузу** и ждёт `/yes`:

```
⏸ Жду подтверждения. Предложено: выполнить команду: git push origin main.
   НЕ ВЫПОЛНЕНО. Скажи владельцу, что нужно подтвердить это действие
   (/yes — принять, /no — отклонить), и не повторяй попытку.
```

Почему так, а не «запрещённое слово в команде»: чёрный список умеет только то,
о чём кто-то уже подумал, — `sh -c`, `find -delete`, `| xargs`, переменная с
именем команды и `curl -T` проходили через него целиком. Здесь не выполнено
ничего, что способно писать, и цена ошибки — одно лишнее `/yes`, а не машина.

Расширить список можно, но ручка называется `shell_trust` не «allow», и вот
почему: имя в ней означает «и его пишущие режимы тоже»:

```yaml
tools:
  shell_trust: [git]   # git push пойдёт без спроса
```

Это решение о доверии, а не настройка безопасности, поэтому `eva doctor` печатает
содержимое списка отдельной строкой с пояснением.

## Данные и секреты

В репозитории **нет** ни конфига, ни базы, ни ключей — только код.
`config.example.yaml` с заглушками, реальный `config.yaml` и `*.db` в `.gitignore`.
Живут в `~/.eva/` (путь к конфигу переопределяется `EVA_CONFIG_PATH`).
`eva init` ставит конфигу `600`: на общей машине читаемый ключ — это просто
читаемый ключ.

Секреты — только в `~/.eva/config.yaml` и в переменных окружения. Ни один ключ не
попадает в логи, в отчёт `doctor` (там длина, не значение) и в чат.
